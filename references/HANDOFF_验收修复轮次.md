## 1. ⚠️ 第一优先：Word「发现无法读取的内容」仍待用户确认

用户已连续三轮反馈打开成品时 Word 报此错。**沙箱里没有 Word，最终判据只能是用户实测**（长期约束，见 §4）。

已修的成因（全部属于「**良构 ≠ 合法**」——XML 解析没问题、zip 也完好，但 Word 拒绝打开）：

| # | 成因 | 状态 |
|---|---|---|
| 1 | `<w:suff>` 写在 `<w:numFmt>` 之前（违反 CT_Lvl 的 sequence） | 已修（第二/三轮） |
| 2 | `<w:jc>` 在 `<w:ind>` 前、`<w:outlineLvl>` 在 `<w:spacing>` 前、往只有 `<w:sz>` 的 Normal 里 append `<w:rFonts>` | 已修 |
| 3 | `docGrid` append 到 `printerSettings` 之后、`updateFields` 塞到 settings 最前、`w:num` 落到 `numIdMacAtCleanup` 之后 | 已修 |
| 4 | **样式重名**（注入的"标题 1"/"图标题"与模板已有样式撞车） | 已修：样式名加 `FGW` 前缀 + 注入时兜底改名 + Normal 按「默认样式 → styleId → **名字**」三级查找 |
| 5 | **批注被覆盖写**：原有批注被抹掉、document.xml 里它们的标记变成**悬空引用**，新批注 id 从 0 重排**撞 id** | **第四轮新修**（陷阱 #20）——这是本轮唯一**可复现、已量化**的成因：对成品再跑一遍 → 14 处悬空引用 + 9 处重复 id |
| 6 | **编号克隆复制了源身份**：两条 `abstractNum` 抢同一个 `styleLink`、同一批级别 `pStyle` | **第四轮新修**（陷阱 #15 补充） |

**下一轮开场就该做的事**（不要先猜，先取证）：

```bash
python3 scripts/diagnose_docx.py <用户手上那个报错的成品.docx>
python3 scripts/diagnose_docx.py <对应的原始文档.docx>     # 对照：原件本来干不干净
```

`diagnose_docx.py` 是**只读**排查工具，专查 XML 良构检查发现不了的那类损坏：元素顺序违反 sequence、
样式名/styleId 重复、`pStyle`/`numId`/关系 `r:id` 悬空、缺 Content-Type，**以及本轮新增的批注一致性
（悬空引用/重复 id/区间不配对）与编号身份链接重复**。输出 JSON、退出码 2 表示有问题。
**两个文件都要查**——如果原件本来就带问题，那就不是我们引入的。45 步已把这两项新检查也纳入硬失败。

若 `diagnose_docx.py` 报 **clean 但 Word 仍报错**：把成品在 Word 里「另存为」后再 `diagnose_docx.py`
对比两份的差异（Word 修复时会重写它认为非法的部分），差异处即真凶。

## 2. 已实现的功能全景（都已跑通并有测试锁定）

**方案C 阶段2/3（样式注入）**——规范值不再写成段落直接属性，而是由**注入的 canonical 命名样式**
承载，段落只指派 `pStyle` 并清掉样式已承载的直接属性。45 步有**全坍缩不变量**兜底（属性仍由
`direct`/`numbering` 供给且值不合规即硬失败退 2）。契约细节见陷阱 #12。

四轮验收累计落地：

- **文档网格**每页 41 行 / 行距 15.6 磅（`docGrid` + settings 的 compat 块 + `Normal`=五号）；
- **目录**制表位按字符数写进 TOC 样式（点线、页码不换行）——已通过验收；
- **首行缩进**只写字符单位，Word 显示"2 字符"——已通过验收；
- **一~四级标题加粗**，加粗由样式承载（连 run 上的直接加粗、显式取消加粗、抢戏的字符样式一起清）；
- **标题/图表标题删首尾空格**；
- **图/表标题改用 Word 自动编号**（`图%1`/`表%1`、`suff=tab`），编号**挂在样式上**——已通过验收；
- **标题自动编号改挂注入的四级 canonical 列表**（本轮，见 §3）；
- **封面外空行**套正文样式；**图片/文本框段落**不套（固定行距会把图裁成一行）；
- **表格**默认值（`tblInd`/`tblCellMar`/`vAlign`）；
- **批注合并**进文档已有批注（本轮）。

## 3. 本轮修掉但**尚未经用户确认**的事

下一轮验收请重点看：

1. **标题编号逐级归零**（用户第二次报同一现象，上一轮的修法不够）。根因不是 `lvlRestart=0`，而是
   **各级标题分属不同的编号定义**——Word 的逐级归零只在同一个列表实例内成立。现在注入一条**四级
   multilevel 列表**（`一、`/`（一）`/`1.`/`（1）`），所有原本自动编号的已确认标题统一改挂它、
   `ilvl=级别-1`。详见陷阱 #19。**验收看**：二级在每个一级下从 `（一）` 重新开始；三级、四级同理。
2. **惯例不编号章节不再被自动编号**（摘要/前言/结论/参考文献/附录/致谢…）：以前它们挂着模板的自动
   编号，会渲染成「三、结论」并顶掉后面同级标题的序号。**验收看**：结论/参考文献等前面没有序号，
   且它们前后的一级标题序号是连的。
3. **文字里已有序号的标题不再叠自动编号**（否则「一、一、绪论」）。
4. **原有审阅批注不再被抹掉**：文档自带的批注会保留，本工具的批注接在后面。**验收看**：原批注还在，
   且 Word 不再提示文档需要修复。

## 4. 铁律与长期约束（别踩）

- **红线**：只做格式、**不改原文**、判定值**只来自 spec**、**不手写 `fixes.json`**。
- **沙箱没有 Word / soffice**：渲染类结论**只能靠用户实测**。凡是"Word 里看起来如何"的判断，
  写代码时就要想好怎么让用户一眼验证，别自己拍脑袋下结论。
- **良构 ≠ 合法**：`45` 的 XML 良构检查发现不了元素顺序、样式重名、悬空批注这类问题。往 XML 里插元素
  一律走 `_get_or_make`（自动查 `docxcommon.ELEMENT_ORDER` 按序插），**别 append 了事**；新增一类
  结构性损坏时，把探测器写进 `docxcommon` 并让 45 与 `diagnose_docx.py` **共用**。
- **写任何"部件级"内容前先读已有的**（批注是血的教训 #20）：文档里可能已经有同类内容，覆盖写等于
  改原文 + 留下悬空引用。
- **安全阀**（陷阱#5）：仅凭形状认出、没有样式/大纲级别撑腰的标题与图表标题（`pattern`），
  **绝不自动改文字**，也不指派 canonical 样式（否则下一轮它会凭样式"转正"、绕过安全阀）。
- **共享对象不可原地改**：`abstractNum`、字符样式都可能被多段共享，要改就**克隆**或**摘引用**，
  原地 mutate 会溢到无关段落（老 bug #17）；**克隆还必须摘掉源身份**（#15）。
- **同一规则只写一份**：canonical 样式/编号、区域划分、字符样式判断、结构性探测器都已收敛到共享模块。
  再出现"两处各写一遍"必然漂移——这是本项目栽过最多次的地方。
